# Phase 7 · 撤销/重做 + 进度 + 多图导入 Implementation Plan

> 执行：subagent-driven。范围:全局 undo/redo、补齐进度提示、多图导入。不碰 nesting 算法(Phase8)。

**Goal:** `Ctrl+Z`/`Ctrl+Y` 撤销/重做覆盖所有操作(移动/缩放/旋转锁角/改白边/切割/修补/删除/导入/整理);所有耗时操作有进度;一次可导入多张图(追加)。

## 锁定决策 — Undo 架构(前端快照栈 + 追加式数据)
- **数据存追加不删**:前端 `partData`/`imgElById` 与后端 `PARTS` **永不删除**条目(删除/切割/修补只是把旧零件移出「活动集」,数据保留),这样 undo 能从保留数据重建任何曾出现的零件。后端 `api_cut`/`api_brush` 去掉 `del PARTS[id]`(只 add 新件;旧件留存)。
- **快照内容**:`snapshot = { activeIds:[...], tf:{ id:{left,top,scaleX,angle,locked} }, g:{borderPx,pageWmm,pageHmm,bleedMm} }`。
- **栈**:`undoStack`/`redoStack`;`pushSnapshot()` 在每个操作完成后调用(并清空 redoStack);`undo()` 把当前 push 到 redoStack、弹 undoStack 顶恢复;`redo()` 反向。栈深封顶(如 50)。
- **恢复 `applySnapshot(s)`**:① 全局:`borderPx=s.g.borderPx`、纸框尺寸、bleed,并同步后端(set_border/set_page/set_bleed);② 活动集:移除画布上不在 `activeIds` 的 group;对 `activeIds` 中缺失的 group 用保留的 `partData/imgElById` 重建(buildGroupSync);③ 应用每个零件 transform(left/top/scaleX/scaleY=scaleX/angle/locked,锁角补洋红框);④ requestRenderAll。
- **首次快照**:初始化(空场景)push 一个基线快照,使最早的导入也可撤销。

### Task 2: 前端 undo/redo + 多图导入 + 补齐进度

**Files:** `web/index.html`、`web/app.js`。

**要求:**
- **数据追加**:`btn-delete`、切割 confirm、brush 替换等处,**不再** `partData.delete/imgElById.delete`;只把 group 移出画布并从 `objById` 移除(objById = 当前活动 group 映射)。保留 `partData`(id→数据)与 `imgElById`(id→图)。
- **快照与栈**:实现 `snapshot()`(读 objById 算 activeIds + 各 group transform + 全局 borderPx/pageWpx→mm/pageHpx→mm/bleedMm)、`pushSnapshot()`、`undo()`、`redo()`、`applySnapshot(s)`(见决策)。在这些操作末尾调用 `pushSnapshot()`:导入完成、object:modified(移动/缩放/旋转)、markLocked/markFree、删除、切割 confirm、brush 替换、整理排版完成、改白边(commitBorder)、改纸张、改出血。
- **快捷键**:`Ctrl+Z`→undo,`Ctrl+Y` 或 `Ctrl+Shift+Z`→redo(忽略输入框聚焦时)。
- **applySnapshot** 重建缺失 group 用 `buildGroupSync(partData.get(id))`(已保留),再 set transform。
- **多图导入**:`<input id="file" multiple>`;onchange 遍历所有选中文件,逐张 segment+addPart(进度按文件推进),全部完成后 fitView + 一次 pushSnapshot。
- **补齐进度**:切割(预览/确认)、修补(brush)期间 showProgress/hideProgress;已有的 import/nest/export 保留。
- 不破坏 cutMode/brushMode/rotation/pan/zoom/border/export。
