# AutoPSTool 刀模流水线重设计 — 设计文档

- 日期：2026-06-26
- 状态：已通过用户逐节确认，待写实施计划
- 决策：整体策略 **方案 2（后端干净重写 + 前端画布重做）**；抠图 **引擎 C（AI 抠图 + CV 边界精修）**

## 1. 背景与目标

AutoPSTool 用于把「白底卡通图」自动做成贴纸：沿主体轮廓外扩生成刀模线，把主体抠出，再把所有主体紧凑排到固定画布（A4），最终给贴纸/切割机一份成品。

当前实现（`Gemini/` Flask + fabric.js，`src/` Illustrator COM）存在两类硬伤：

1. **自动化不稳定**：魔棒泛洪 + 阈值抠图对「白底 + 主体内部白 + 低色差边缘」反复翻车，被迫一再调 `tolerance` 等参数，违背「省力」初衷。
2. **功能半吊子**：多处看似实现实则有 bug（如 `/api/process_sticker` 调用了不存在的 `process_single_sticker`，整条出 PDF 链路是坏的）；常量在三个文件各抄一份；存在多份重复实现。

**本次目标**：围绕清晰的数据模型重写后端流水线、重做前端交互画布，得到一个**一键启动、稳定、所见即所得**的工具。验收标准：一批代表性真实白底图，**不调任何参数**，一键直接产出可用结果。

### 理想使用流程（主线）

导入白底卡通图（图中 1 个或多个主体）→ **一键**沿主体轮廓外扩生成刀模线、抠出主体 → 自动把所有主体最紧凑地排到固定画布 → 人工干预两件事：①调整主体之间的相对大小 ②把过大/形状别扭的单一主体切成带出血的多块（贴时沿切割线拼回）→ 导出成品。

### 非目标（第一版不做，留接口后期加）

SVG / PDF 导出、专色分版、旋转排版、批量队列、撤销历史。当前坏掉的 `/api/process_sticker` 与 `core_engine.py` / `nesting_packer.py` 的重复实现全部废弃，逻辑收敛到新 `app/` 模块。

## 2. 关键术语澄清

- **主体分离（auto-split）**：一张图含多个主体时，自动拆成多个独立**零件**（用户素材约一半单主体、一半多主体，A 方案：默认自动拆）。
- **手动切割（cut）**：不是分主体，而是把**单一**过大/形状别扭的零件（如长条）切成几块，每块缩放后都能合理放进固定画布；切口两侧**重叠出血（bleed）**，物理贴合时沿切割线拼回。

## 3. 环境与依赖

- 项目内本地环境：**conda 项目内 `.conda`，Python 3.11**
  - `conda create -p D:\study\AutoPSTool\.conda python=3.11`
  - 理由：用户本来用 conda，3.11 有现成解释器；Python 3.14（本机默认）对 `onnxruntime`/`rembg` 大概率无轮子；conda 环境不可剪切移动，故新建而非搬迁旧 `autopstool` 环境。
- 旧的 `autopstool` conda 环境保留不动，新环境验证可用后用户自行删除。
- `requirements.txt`：`flask`、`opencv-python`、`numpy`、`shapely`、`pillow`、`rembg`、`onnxruntime`、`svgpathtools`、`pypotrace`（矢量化，导 SVG 时才用，第一版可暂缓安装）。
- `rembg` 首次运行会下载约 170MB 模型，之后离线可用（用户已确认可接受）。

## 4. 整体架构

```
AutoPSTool/
  app/                    后端（Flask）
    server.py             起服务 + 托管前端页面 + API 路由
    segmentation.py       引擎C：AI 抠图 + CV 边界精修 + 多主体连通域分离
    part_builder.py       单主体 → 零件（白边、刀模轮廓、出血切割）
    nesting.py            Shapely 紧凑排版
    exporter.py           渲染最终 PNG（图 + 白边 + 洋红刀模线）
    geometry.py           像素/mm、A4 常量、坐标换算（单一来源）
  web/
    index.html, app.js, style.css   交互画布前端
  tests/
    fixtures/cats_11.png  主测试样张（十一只猫，白/橘/灰，内部白区 + 毛刺边缘）
    ...                   各模块独立测试
  start.bat               双击：激活 .conda → 起服务 → 自动开浏览器
  requirements.txt
```

- **Flask 同时托管前端**：访问 `http://127.0.0.1:5000` 直接出界面，前端同源调 API，去掉单独开 html 与 CORS。
- **一键启动 `start.bat`**：激活项目内 `.conda` → 启动 `server.py` → 服务就绪后 `webbrowser.open` 自动打开页面。
- **物理常量集中到 `geometry.py` 一处**：`PIXEL_RATIO=10`（1mm=10px）、A4=2100×2970px、白边 `offset`、出血 `bleed`、排版间距 `padding`。根治「三文件各抄一份」。

## 5. 核心数据模型

整个工具围绕统一的 `Part`（零件）对象，前后端共享字段：

```
Part {
  id
  image_layer   : RGBA 位图（主体 + 白边底，透明背景）
  cut_contour   : 刀模轮廓（多边形点集 / 矢量路径）
  x, y          : 在画布上的位置
  scale         : 缩放比例（调相对大小）
  rotation      : 角度（暂固定 0，后期可开）
}
```

- **图片层与矢量刀模层显式分离** —— 这是「导出格式可插拔」（后期加 SVG/PDF 轻松）的根本保证。
- 一次切割 = 把 1 个 `Part` 换成 2 个带重叠出血的新 `Part`。
- 前端画布即一组 `Part` 的可视化与拖/缩/切；「整理」「导出」都是对这组 `Part` 做变换。

## 6. 后端流水线（每步可独立测试）

1. **抠图（引擎 C，`segmentation.py`）**
   - 主力：`rembg` AI 模型出主体 mask（搞定白底 / 主体内部白 / 低色差边缘，近零参数）。
   - 精修：CV 边界清理——去毛刺、`findContours(RETR_EXTERNAL)` 取最外轮廓填实（内部白不再变透明洞）、小噪点过滤。
   - **多主体自动分离**：mask 上做连通域，每个主体出一个零件。
2. **白边 + 刀模轮廓（`part_builder.py`）**：椭圆核膨胀 `offset` 像素 = 白边；膨胀后掩膜的外轮廓即刀模线。
3. **切割（按需，`part_builder.py`）**：SDF 半平面把单个零件切成两块；切口两侧重叠 `bleed` 以便物理拼贴；切口保持平直（膨胀掩膜再与平直边界 AND，斩掉切口处的弧形白边）。
4. **紧凑排版（`nesting.py`）**：把零件轮廓离散为 Shapely 多边形，按面积降序，Bottom-Left-Fill 网格扫描找左上角无碰撞位；碰撞用 `buffer(padding/2)` 保证物理间距 ≥ `padding`。第一版不旋转。
5. **导出（`exporter.py`）**：把所有零件的图片层贴到 A4，再把每个零件刀模轮廓以洋红 `#FF00FF` 描到**同一张 PNG** 上。

## 7. 前端交互画布（所见即所得）

- 导入图片 → 后端抠图分离 → 抠好的零件直接散落在 A4 画布上。
- 操作：拖动移动、缩放改相对大小、选中零件画线切割（切成带出血两块）、删除。
- **「整理」按钮**：随时把当前所有零件紧凑重排，之后还能再手动微调。
- **「导出」按钮**：下载最终 PNG。
- 技术：第一版继续用 fabric.js（已有基础），重点是交互**完整、无 bug**，而非堆功能。

## 8. 测试与验收策略

- 每个后端模块带独立测试；保留现有 `output/case*` 合成图做回归。
- **主测试样张**：`tests/fixtures/cats_11.png`（用户提供的十一只猫图，白/橘/灰、主体内部白区、毛刺边缘）。重点验证：①11 个主体全部正确分离；②白猫不被当背景、不出现内部透明洞；③毛刺边缘抠得干净。
- 抠图单独提供「调试视图」：可单看某张图的 mask 结果，快速判断 AI 与精修是否到位，而非跑完整条流水线才发现问题。
- **验收标准**：一批代表性真实白底图，不调任何参数，一键直接产出可用结果。

## 9. 实施推进顺序（建议）

1. 环境：建 `.conda`（py3.11）+ `requirements.txt` + `start.bat`。
2. `geometry.py` 常量单一来源。
3. `segmentation.py`（引擎 C）+ 调试视图 —— 用 `cats_11.png` 验证后再继续。
4. `part_builder.py`（白边 / 刀模 / 切割）。
5. `nesting.py`（紧凑排版）。
6. `exporter.py`（单张 PNG）。
7. `server.py` 托管前端 + API 串联。
8. 前端画布交互（拖 / 缩 / 切 / 整理 / 导出）。
9. 废弃旧 `Gemini/app.py` 坏路由、`core_engine.py`、`nesting_packer.py`、`src/`（如不再需要）。
